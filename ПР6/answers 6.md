1. Что такое Viewport meta tag и почему он важен для адаптивного дизайна?
Это мета-тег в <head>
Он сообщает браузеру, что ширина страницы должна быть равна ширине экрана устройства (а не 980px по умолчанию, как в старых мобильных браузерах), а масштаб - 1:1. Без него мобильные устройства отображают сайт в уменьшенном «десктопном» виде, и медиа-запросы работают некорректно. Это основа адаптивной вёрстки.
2. Какие основные подходы к созданию адаптивных макетов вы использовали (Fluid, Adaptive, Responsive)?
•	Fluid (резиновый) - размеры в %, fr, vw, rem, clamp(); контент плавно перестраивается. Использован в .container (max-width: 1200px, width: 100%), .features-grid (1fr), типографике (clamp()).
•	Adaptive (адаптивный) - под фиксированные брейкпоинты с медиа-запросами. Использован в @media (max-width: 1024px/768px/480px).
•	Responsive (отзывчивый) - комбинация fluid + adaptive + медиа. Именно он реализован в работе.
3. Как работает Mobile First подход и в чем его преимущества перед Desktop First?
Mobile First - стили пишутся сначала для мобильных, потом расширяются через min-width медиа-запросы. Desktop First - наоборот, базовые стили для десктопа, потом сужаются через max-width.
Преимущества Mobile First:
•	Меньше CSS на мобильных (быстрее загрузка).
•	Проще добавлять, чем убирать стили.
•	Приоритет - контенту, а не декору.
•	Лучшая производительность на слабых устройствах.
В работе использован Desktop First (по инструкции - max-width), но для production чаще рекомендуют Mobile First.
4. Какие единицы измерения наиболее предпочтительны для адаптивной верстки и почему?
•	rem - относительно html (базовый размер шрифта). Удобно для типографики и отступов, легко масштабировать через html { font-size: ... } в медиа-запросах.
•	% - для ширин контейнеров.
•	vw/vh - для привязки к размеру окна (например, clamp()).
•	fr - для Grid-колонок.
•	em - для компонентов, зависящих от своего шрифта.
Не рекомендуются: px для типографики (плохо масштабируется), абсолютные cm/mm/pt.
5. Как функция clamp() помогает создавать адаптивную типографику?
clamp(min, preferred, max) возвращает значение в диапазоне. 
6. Какие основные брейкпоинты вы использовали и как определили эти значения?
•	1024px - планшет (горизонтальный).
•	768px - планшет вертикальный / граница мобильных.
•	480px - маленькие мобильные.
Значения выбраны по типовым размерам устройств (iPad, iPhone, Android). Это не «магические числа», а практические ориентиры: 768px - типичная ширина iPad портрет, 1024px - iPad landscape, 480px - старые смартфоны.
7. Как медиа-запросы @media помогают создавать адаптивные стили? Приведите пример синтаксиса.
@media применяет CSS только при выполнении условия (ширина, ориентация, разрешение и т.д.).
8. В чем разница между max-width и min-width в медиа-запросах и когда использовать каждый?
•	max-width: 768px - стили применяются, когда ширина ≤768px (Desktop First, «сужение»).
•	min-width: 768px - стили применяются, когда ширина ≥768px (Mobile First, «расширение»).
max-width удобен для быстрого «подлатывания» десктопного макета; min-width - для чистого Mobile First. В работе использован max-width (по инструкции).
9. Как сделать изображения адаптивными и какие CSS-свойства для этого используются?
img {
  max-width: 100%;
  height: auto;
}
max-width: 100% не даёт картинке вылезать за родителя, height: auto сохраняет пропорции. Дополнительно:
•	srcset / sizes - для разных разрешений.
•	<picture> - для art-direction.
•	object-fit: cover - для кадрирования.
10. Какие инструменты браузера помогают тестировать и отлаживать адаптивный дизайн?
•	Режим адаптивного дизайна (Ctrl+Shift+M в Chrome/Firefox) - эмуляция устройств.
•	Device Toolbar - выбор готовых пресетов (iPhone, iPad, Galaxy).
•	Ruler / сетка - измерение блоков.
•	Throttling - эмуляция медленного интернета.
•	Lighthouse - аудит производительности и адаптивности.
•	Responsive Design Mode в Firefox - показывает брейкпоинты.
•	CSS Overview - анализ использованных медиа-запросов.
