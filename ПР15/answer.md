# Ответы на вопросы (React)

## 1. Функциональные vs классовые компоненты
- **Функциональные** — простые функции, возвращают JSX. С хуками (React 16.8+) имеют весь функционал классов: состояние (`useState`), побочные эффекты (`useEffect`), контекст (`useContext`). Короче, читаемее, лучше оптимизируются.
- **Классовые** — `class extends React.Component`, работают с `this.state`/`this.setState` и методами жизненного цикла (`componentDidMount` и т.д.).
- **Когда что:** в новом коде — **только функциональные** (рекомендация React). Классы — для legacy-кода, Error Boundaries (всё ещё требуют класс) и очень редких случаев.

## 2. props vs state
- **props** — входные параметры компонента, передаются извне, **только для чтения** внутри компонента. Обеспечивают однонаправленный поток данных.
- **state** — внутреннее состояние компонента, **изменяется** через `setState` / сеттер `useState`. Изменение вызывает перерисовку.
- **Правила:** props нельзя мутировать; state меняется только через setter; нельзя читать state сразу после setState (асинхронно); не хранить в state вычисляемые значения (лучше вычислять при рендере или через `useMemo`).

## 3. Lifting state up
Поднятие состояния — перенос state в **ближайший общий родитель**, если он нужен нескольким дочерним компонентам. Родитель хранит состояние и передаёт его детям через props + колбэки для изменения.
**Когда нужно:** два и более компонента должны синхронизироваться (например, фильтр и список, две формы, зависящие от одного значения).

## 4. Методы жизненного цикла классов
- **Монтирование:** `constructor` → `render` → `componentDidMount` (запросы, подписки, таймеры).
- **Обновление:** `shouldComponentUpdate` (оптимизация) → `render` → `componentDidUpdate` (реакция на изменение props/state).
- **Размонтирование:** `componentWillUnmount` (очистка: `clearInterval`, `removeEventListener`, отмена запросов).
- **Ошибки:** `componentDidCatch`, `getDerivedStateFromError` (Error Boundaries).
- **Устаревшие (не использовать):** `componentWillMount`, `componentWillReceiveProps`, `componentWillUpdate`.

## 5. Хуки useState и useEffect. Правила хуков
- **useState(initial)** — возвращает `[value, setValue]`. Изменение через сеттер вызывает ре-рендер.
- **useEffect(fn, deps)** — выполняет побочный эффект после рендера:
  - `deps = undefined` → после **каждого** рендера;
  - `deps = []` → **один раз** при монтировании (cleanup — при размонтировании);
  - `deps = [a, b]` → когда меняются `a`/`b`;
  - возврат функции из `fn` — cleanup (отписка, таймеры).
- **Правила хуков:** вызывать **только на верхнем уровне** функции (не в условиях/циклах/вложенных функциях) и **только из React-функций** (компонентов и кастомных хуков). Иначе нарушается порядок вызовов.

## 6. Ключи (keys) в списках
`key` — уникальный идентификатор элемента в списке. Помогает React понять, какие элементы добавлены/удалены/перемещены, и переиспользовать DOM-узлы вместо полной перерисовки.
**Правила:** ключ должен быть стабильным и уникальным среди соседей. Использовать `id` из данных, **не** индекс массива (если список сортируется/меняется).

## 7. События в React vs нативный JS
- **Синтетические события:** React оборачивает нативные события в `SyntheticEvent` (кроссбраузерность, единый API: `e.target`, `e.preventDefault()`, `e.stopPropagation()`).
- **CamelCase** в именах: `onClick`, `onChange`, `onSubmit`.
- **Передаётся функция**, а не строка: `onClick={handleClick}`, не `"handleClick()"`.
- Делегирование на корне (React 17+ — на root-элементе приложения), автоматическая очистка при размонтировании.
- `this` в классах нужно биндить (или использовать стрелочные функции), в функциональных — не нужно.

## 8. Управляемые vs неуправляемые компоненты
- **Управляемые (controlled):** значение поля хранится в state, `value={state}` + `onChange`, React — единственный источник истины. Легко валидировать, синхронизировать, форматировать.
- **Неуправляемые (uncontrolled):** значение хранится в DOM, доступ через `ref` (`useRef`/`createRef`). Проще для простых форм, но сложнее валидация.
- **Выбор:** управляемые — по умолчанию, особенно для сложной логики. Неуправляемые — для файлов (`<input type="file">`) и простых случаев/интеграций с не-React библиотеками.

## 9. Context в React
`React.createContext(default)` создаёт контекст. `Provider` передаёт значение вниз по дереву, `useContext(Context)` / `Context.Consumer` читают его **без** проброса props через все уровни.
**Когда использовать:** глобальные данные, нужные многим компонентам на разных уровнях — тема, язык, авторизация, настройки.
**Не злоупотреблять:** для часто меняющихся данных или сложной бизнес-логики лучше Redux/Zustand — Context перерисовывает всех потребителей при изменении.

## 10. Кастомные хуки
Кастомный хук — **функция с префиксом `use`**, которая вызывает другие хуки и инкапсулирует переиспользуемую логику (не JSX!). Пример: `useLocalStorage`, `useFetch`, `useDebounce`, `useForm`.
**Преимущества:** переиспользование логики (не UI), чистота компонентов, тестируемость, композиция.
**Правила:** имя начинается с `use`; внутри — обычные правила хуков (top-level, только из React-функций); возвращает всё, что нужно (значение, сеттер, флаги).
