 
1. Три области в GitРабочий каталог: Папка на ПК, где вы редактируете файлы. Git пока не сохраняет эти изменения.Индекс (Staging): Буферная зона (черновик). Сюда собираются файлы, готовые к сохранению.Репозиторий: Локальная база данных (.git), где коммиты хранятся навсегда.2. Что делают команды?git add: Переносит изменения из каталога в индекс.git commit: Сохраняет слепок из индекса в локальный репозиторий.git push: Отправляет коммиты из локального репозитория в удаленный (например, GitHub).3. Зачем нужны информативные сообщения?Чтобы вы и ваша команда спустя время могли понять зачем и что было изменено, не читая код. Это упрощает поиск багов и откат изменений.4. git add имя_файла vs git add .git add имя_файла: Индексирует один файл. Нужен для разделения разных правок на отдельные коммиты.git add .: Индексирует все изменения в текущей папке. Нужен, когда готов весь этап работы.5. Что показывает git status?Состояние файлов: красные — изменены, но не добавлены; зеленые — добавлены в индекс; сообщение working tree clean — все изменения сохранены в коммит.6. Зачем нужен git remote add origin URL?Связывает локальную папку с удаленным репозиторием. origin — это просто стандартное имя-сокращение для ссылки на этот репозиторий.7. Зачем флаг -u в git push -u origin main?Он связывает текущую локальную ветку с удаленной. При следующих отправках можно писать просто git push без указания origin main.8. Ветка по умолчаниюЭто главная ветка с чистым кодом проекта. Раньше создавалась master, сейчас стандарт — main. Важна как единая точка отсчета для всей разработки.9. Как смотреть историю коммитов?Через команду git log. Видно: хэш (id) коммита, автора, дату и сообщение. Для краткости используют git log --oneline.10. Что если сделать git commit без git add?Коммит не создастся. Git сохраняет только то, что предварительно добавлено в индекс. Изменения останутся просто в рабочей папке.
